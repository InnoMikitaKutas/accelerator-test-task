## 🔴 Critical

### C1 — Stored XSS via unsanitized SVG logo
**Files:** `src/shared/storage/file-validation.ts:34-35`, `src/shared/storage/image.service.ts:31-32`,
`src/modules/branding/branding.service.ts:38-49`, `src/shared/storage/local-storage.adapter.ts:18-24`
**Requirement:** FR-037, §13 security

`logoFilePipe()` accepts `image/svg+xml`; `processLogo()` returns SVG bytes **unchanged**
(`if (mime === 'image/svg+xml') return { buffer: input, contentType: mime, ext: 'svg' }`);
`uploadLogo()` stores it and returns the URL; the local adapter serves from
`STORAGE_PUBLIC_BASE_URL` (default `http://localhost:3000/static`) — **same origin as the API**.
A trainer can upload an SVG containing `<script>`; it is served verbatim and, because
`branding.getByTrainer()` is a public cross-tenant read used to theme players, executes in other
users' browsers in the app origin → session theft / account takeover. Validation also trusts the
client-supplied `file.mimetype` (`file-validation.ts:26`), not magic bytes (raster is saved by
sharp re-encode; SVG is the hole).
**Fix:** drop SVG, or sanitize (DOMPurify/svgo, strip `script`/`on*`/`foreignObject`/external refs)
and serve uploads from a cookieless origin with `Content-Disposition: attachment`; validate by file
bytes, not declared MIME.

## 🟠 High

### H1 — Impersonation 1h window is dead; abandoned sessions never close
**Files:** `src/shared/auth/token.service.ts:58-63` & `:132-141`,
`src/shared/auth/guards/jwt-auth.guard.ts:37-40`, `src/modules/impersonation/impersonation.service.ts:58-76`
**Requirement:** FR-015, FR-016, BR-009, NFR-007

`issueImpersonation()` signs through `signAccess()`, which hardcodes
`expiresIn: ACCESS_TOKEN_TTL` (900s). So the impersonation JWT expires in **15 min**, while the
`impersonationExp` claim and the cookie `maxAge` say **1h**. The guard's `impersonationExp` check is
therefore unreachable (the JWT `exp` always fires first). Impersonation silently ends at 15 min,
then auto-refresh (admin's `rt`) reverts to the admin. Separately, `closeOpenLog()` runs **only** in
`exit()` and there is **no expiry job** (the only background process is the outbox poller), so any
impersonation that expires or is abandoned leaves an `ImpersonationLog` with `endedAt=null` forever
→ FR-016 duration report is wrong.
**Fix:** sign impersonation tokens with `expiresIn: IMPERSONATION_TTL`; add a sweep (or
outbox-scheduled job) to close logs at expiry.

### H2 — Deactivation does not revoke active sessions
**Files:** `src/modules/users/user-admin.service.ts:103-115` (contrast `src/modules/users/anonymization.service.ts:33`)
**Requirement:** FR-013, BR-010

`deactivate()` sets status `INACTIVE` + audits but never revokes tokens. `JwtAuthGuard` validates
only JWT signature/exp (not DB status), so a deactivated user keeps a **working access token for up
to ~15 min** (refresh *is* blocked at `auth.service.ts:90-92`). GDPR-delete correctly calls
`revokeAllForUser`; deactivate should too — an admin disabling an abusive/compromised account
expects immediate lockout.
**Fix:** `await this.tokens.revokeAllForUser(id)` inside `deactivate()`.

## 🟡 Medium

### M1 — `/join` existing-user branch ignores link type & single-use
**File:** `src/modules/sharelinks/join.service.ts:154-200`
**Requirement:** FR-018, FR-028, FR-029, BR-011

`associateExisting()` always calls `associatePlayer()` regardless of `link.type`, and on this path
only does `useCount + 1` — it never marks a `unique` link `ACCEPTED`/`active:false`. So an existing
logged-in user clicking a single-use **coach-invite** link gets a *player* association, and the link
stays consumable. (The new-user `registerNew` path handles type + single-use correctly.)
**Fix:** branch on `link.type`; reject/handle coach links in the existing-user path and enforce
single-use consumption there.

### M2 — Trainer can override a coach from any org
**Files:** `src/modules/availability/availability.service.ts:86-98`, `src/modules/availability/availability.repository.ts:113-121`
**Requirement:** FR-031, NFR-011

`createOverride()` gates on `repo.trainerExistsForCoach(dto.coachId)`, but that method only checks
the coach **exists globally** — no `trainer_coach_associations` check (name is misleading). The
override row is written with the caller's own `trainerId`, so RLS `WITH CHECK` passes. A trainer can
create (and audit-log) an override referencing any org's coach. Advisory today (BR-012) but a real
cross-tenant authorization gap; escalates once Epic-02 consumes overrides.
**Fix:** verify an active `(currentTrainerId, coachId)` association before allowing the override.

### M3 — No real 48h approval auto-deny
**Files:** `src/modules/family/purchase-approval.service.ts:108-125`, `src/modules/family/family.repository.ts:199-213`
**Requirement:** FR-024, BR-008

Expiry is computed lazily at read (`toResponse` shows `EXPIRED`) and `decide()` rejects expired, but
the DB row stays `PENDING` forever and no parent/child notification fires — there is no sweep/job
(architects' R7). `countPending` *does* correctly exclude expired, so the UI badge is fine, but the
"auto-deny" is not a persisted terminal transition for downstream/Epic-05.
**Fix:** periodic `expiresAt` sweep (or outbox-scheduled job) → terminal state + notification.

### M4 — Upload size enforced after full in-memory buffering
**Files:** `src/modules/branding/branding.controller.ts` (`FileInterceptor('file')`), `src/modules/profiles/profile.controller.ts`, `src/shared/storage/file-validation.ts:25`
**Requirement:** FR-037, FR-038, §13

`FileInterceptor('file')` is used with no `limits`; the 2MB check runs only after multer buffers the
whole body → memory-pressure DoS (auth-gated, so bounded).
**Fix:** `FileInterceptor('file', { limits: { fileSize: 2*1024*1024, files: 1 } })`.

### M5 — CORS ordering + permissive origin
**File:** `src/app.setup.ts:16-29`
**Requirement:** FR-009, §13

`app.enableCors(...)` is registered **after** the CSRF middleware, so CSRF `403`s carry no CORS
headers (masks the real error cross-origin); and `origin: APP_BASE_URL?.split(',') ?? true` with
`credentials: true` reflects **any** origin when `APP_BASE_URL` is unset. Mitigated by
`SameSite=Strict` cookies but still a misconfiguration.
**Fix:** register CORS before CSRF; never fall back to `true` with credentials.

### M6 — Outbox relay reliability
**File:** `src/shared/messaging/outbox.relay.ts:43-77`
**Requirement:** NFR-008 (reliable side effects)

Emails are sent **inside** the `FOR UPDATE` transaction (network I/O under row locks); a permanently
failing message only increments `attempts` with no cap/backoff → retried every 5s forever and can
head-of-line block the batch; send-then-mark-`SENT` can double-send if the commit fails (no
idempotency key).
**Fix:** claim → commit → send → mark; add max-attempts→`DEAD`, backoff via `availableAt`, and an
idempotency key per message.

### M7 — Shallow secret/env validation
**File:** `src/shared/config/env.validation.ts`
**Requirement:** NFR-006, §13

JWT/CSRF secrets are validated only as `@IsString()` (a 1-char or `access==refresh` secret passes),
and runtime-consumed vars (`COOKIE_SECURE`, the TTLs, `APP_BASE_URL`, storage/mailer drivers) are
not in the schema — e.g. `COOKIE_SECURE` unset in prod silently yields non-secure auth cookies, not
caught at boot. (No insecure *defaults* in code — `getOrThrow` is used for secrets.)
**Fix:** `@MinLength(32)` per secret + assert access≠refresh; add runtime vars with validators/defaults.

## ⚪ Low

### L1 — Missing keyset pagination indexes
`share_links` paginates on `(created_at, id)` (`sharelinks.repository.ts:47`) and
`child_purchase_approvals` on `(requested_at, id)` (`family.repository.ts:256`), but neither table
defines the matching composite index (only `users` got one). Fine at MVP scale; add before growth
(NFR-002).

### L2 — No DB CHECK for child age 1–18
`profiles.ts:54` stores `age` as plain `integer`; the 1–18 rule (BR-013) is enforced only in the
DTO. Add `check('player_age_range', sql\`age IS NULL OR (age BETWEEN 1 AND 18)\`)`.

### L3 — Login confirms credential validity for inactive/unverified accounts
`auth.service.ts:38-44` verifies the password **before** the status/verified checks, so
`ACCOUNT_INACTIVE` / `EMAIL_NOT_VERIFIED` confirm valid credentials. The unverified branch is
intended (D-1); consider not distinguishing inactive.

### L4 — Availability ignores soft-deleted players
`availability.repository.ts:61-63` and `:84-96` omit `isNull(playerProfiles.deletedAt)`, so Best
Times is readable/writable for soft-deleted players (BR-010 inconsistency vs the family module).

### L5 — Override `reason` not trimmed / not a string
`availability/dto/availability.dto.ts` `OverrideDto.reason` has `@IsNotEmpty()` + `@MaxLength(500)`
but no `@IsString()`/trim, so a whitespace-only reason satisfies FR-031's "required reason."

### L6 — Cursor value not validated
`shared/common/pagination/cursor.util.ts` shape-checks the decoded cursor but not the value; a
tampered `createdAt` becomes `Invalid Date` at `users.repository.ts:65-66` → silently wrong/empty
page (no crash/injection — base64url+JSON is try/caught and values flow through parameterized
queries). Assert `!Number.isNaN(Date.parse(c.createdAt))`.

### L7 — `/join` auto-login while unverified
`join.service.ts:150-151` issues a session for a new (unverified) registrant, but `login`
(`auth.service.ts:42-44`) blocks unverified users — so a registrant who logs out is then locked out
until verifying. Consistent with the verified-allowlist but inconsistent end-to-end (architects' R4,
half-resolved). Decide: don't auto-login on register, or document the allowlist UX.

### L8 — `storage.put(contentType)` dropped by local adapter
`branding.service.ts:41-45` passes a 3rd `contentType` arg, but `LocalStorageAdapter.put(key, body)`
takes 2 and ignores it (leaky abstraction; the future S3 adapter needs it for `Content-Type`).

### L9 — Stale comments
`users.ts:23-25` says minor-login "creation path deferred," but `family.enableChildLogin` implements
it. `sharelink.util.ts:5` claims codes are "retried on insert," but there's no actual 23505 retry
(collision probability is negligible; just fix the comment).

## ✅ Verified correct / done well (do not regress)

- **Multi-tenancy (architects' R1/R2 — highest risk):** dual-axis RLS GUCs
  (`app.current_trainer_id` + `app.current_user_id`) in `drizzle/9999_rls_policies.sql`; all 6
  tenant-owned tables `ENABLE`+`FORCE` RLS; scoped repos route through `TenancyService.runScoped`
  (`set_config(..., is_local=true)`, pool-safe); a separate `BYPASSRLS` **system pool**
  (`SYSTEM_DRIZZLE`) is used for super-admin/outbox/seed/public-resolve. `runScopedTo(parent-supplied
  trainerId)` is contained because queries are always `childId`-scoped + dual-axis RLS.
- **Tokens:** rotation with reuse-detection + multi-tab grace window (R5); `revokeAllForUser` on
  password reset/change/GDPR; email/reset/verification tokens stored **hashed** (sha256) with
  `expiresAt`/`usedAt`; argon2 password hashing.
- **DB invariants:** partial-unique active-coach index `tca_one_active_trainer_per_coach` is present
  in the **generated migration** (`drizzle/0000_*.sql`), the snapshot, and the schema (BR-003/FR-029
  is DB-enforced); M:N player association + sibling partial unique present.
- **Guard chain** wired in the documented order; login/reset/resend throttled (`@Throttle` 5/min);
  CSRF double-submit with a bootstrapped session-id cookie; error filter maps unknowns to a generic
  500 with no stack leakage.
- **Tests:** `tenant-isolation.e2e-spec.ts` proves fail-closed + A-can't-see-B + `WITH CHECK` blocks
  cross-tenant insert across two real DB roles; `token.service.spec.ts` asserts reuse-detection &
  grace; `auth`/`anonymization` specs assert real outcomes.
