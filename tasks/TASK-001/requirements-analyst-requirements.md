# Epic-01: User Management & Authentication — Requirements

> **TASK-001** · Generated by requirements-analyst · 2026-05-29

## Overview

Foundation epic establishing a multi-role user-management system with email/password
authentication, role-based access control (RBAC), multi-tenant data isolation, and the
relationship model the rest of the platform builds on (parent–child accounts,
multi-trainer players, exclusive coach–trainer links). Also delivers Super Admin
operational tooling (impersonation, soft-delete, GDPR delete), availability ("Best Times"
/ "My Times") management, and simple per-trainer portal branding.

**Priority:** P0 — blocks Epic-02 through Epic-08.
**Complexity:** High (auth, 4-role hierarchy, multi-tenancy, parent-child workflows).
**Target architecture:** NestJS layered (Controller → Service → Repository), DTO-validated.

## Functional Requirements

Priority: **H**igh = MVP-blocking · **M**edium = MVP but sequence-flexible · **L**ow = nice-to-have within MVP.

### Authentication & Authorization
- **FR-001** Email/password registration & login. *Acceptance:* valid creds → role-appropriate dashboard; invalid → generic error. **Priority: H** *(US-01.02, §9)*
- **FR-002** Email uniqueness across all users. *Acceptance:* duplicate email rejected with clear message. **Priority: H**
- **FR-003** Email verification required before login (D-1). *Acceptance:* unverified login blocked; verification link expires 24h; resend available. **Priority: H** *(§9, US-01.01)*
- **FR-004** Password reset flow. *Acceptance:* reset link emailed, expires 1h, single-use; password updated on completion. **Priority: H**
- **FR-005** Force password change on first login for admin-created trainers. *Acceptance:* temp-password users routed to reset before dashboard. **Priority: H** *(US-01.01)*
- **FR-006** Session management (issue, refresh, logout, expiry). *Acceptance:* session expires after configured inactivity; logout invalidates. **Priority: H** *(§9, Q-01.07)*
- **FR-007** Login rate limiting / brute-force protection. *Acceptance:* repeated failures throttled. **Priority: H** *(§9, §13)*
- **FR-008** RBAC: each user has exactly one of {SuperAdmin, Trainer, Coach, Player/Parent}; access enforced on both API and UI. *Acceptance:* cross-role access denied at API layer. **Priority: H** *(§9)*
- **FR-009** CSRF protection on state-changing operations. *Acceptance:* state-changing requests require valid token. **Priority: H** *(§13)*

### User Management (Super Admin)
- **FR-010** Global Users directory with pagination, tool-specific search & filters. *Acceptance:* 10k users list <3s paginated. **Priority: H** *(§3, US-01.01)*
- **FR-011** Create Trainer account (Super Admin only; no trainer self-registration). *Acceptance:* trainer created with business+contact data, invite/temp-password issued, appears Active. **Priority: H** *(US-01.01, §9)*
- **FR-012** Edit any user account/profile. *Acceptance:* admin can edit fields any role can edit on themselves. **Priority: M** *(§10 epic AC)*
- **FR-013** Deactivate user (soft delete; history preserved; reactivatable). *Acceptance:* status→Inactive, login blocked, appears grayed in history. **Priority: H** *(US-01.12)*
- **FR-014** Delete user (GDPR; PII anonymized, history retained as "Deleted User"; irreversible). *Acceptance:* name/email/phone/photo anonymized, analytics totals unchanged, logged. **Priority: H** *(US-01.13)*
- **FR-015** Impersonate any user except other Super Admins. *Acceptance:* view switches, sticky banner, 1h expiry, full audit log. **Priority: H** *(US-01.07)*
- **FR-016** Impersonation audit log + report. *Acceptance:* who/whom/start/end/duration queryable. **Priority: H** *(US-01.07, §13)*

### Player / Parent
- **FR-017** Register via static ShareLink → auto-associate with the issuing trainer. *Acceptance:* new account+player profile created, trainer association made, confirmation email. **Priority: H** *(US-01.02)*
- **FR-018** Existing user clicks another trainer's ShareLink → new association, no duplicate account. **Priority: H** *(US-01.02, §9)*
- **FR-019** Multi-trainer separated views with context switcher; isolated data per context; context persists across session. **Priority: H** *(US-01.02, US-01.04)*
- **FR-020** Parent registers as a player (parent can train themselves). **Priority: M** *(§3)*
- **FR-021** Parent creates child profile (name, age 1–18, gender, optional school/photo). **Priority: H** *(US-01.03)*
- **FR-022** Single-trainer prompt vs multi-trainer checklist when creating a child / on new ShareLink. **Priority: M** *(US-01.02, US-01.03)*
- **FR-023** Parent adds/removes child–trainer associations; removal soft-deletes child data with that trainer and cancels upcoming RSVPs. **Priority: H** *(US-01.04)*
- **FR-024** Child purchase approval workflow — USD always requires approval; tokens per-child toggle (default require). 48h auto-deny expiry; email+in-app notify. **Priority: H** *(US-01.05)*
- **FR-025** Child login with constrained permissions (view/RSVP-pending; cannot add trainers, buy tokens, change associations, see parent data). **Priority: H** *(US-01.06)*
- **FR-026** ShareLink blocking for children: child clicking a new-trainer link is blocked; parent emailed a register-CTA. **Priority: H** *(US-01.06)*
- **FR-027** Context switching UI: parent sees "Me" + children; child sees own trainers only. **Priority: M** *(US-01.04, US-01.06)*

### Coach
- **FR-028** Coach invited by trainer via unique ShareLink (single-use, 7-day expiry). **Priority: H** *(US-01.08)*
- **FR-029** Coach assigned to exactly ONE trainer; system rejects activation under a second trainer. **Priority: H** *(US-01.08, §9)*
- **FR-030** Coach sets "My Times" recurring weekly availability (multiple slots/day). **Priority: H** *(US-01.10)*
- **FR-031** Availability-conflict warning + trainer override with required reason (logged). **Priority: M** *(US-01.10)*
- **FR-032** Coach public profile (bio, credentials, certifications, visibility toggle). **Priority: M** *(US-01.11)*

### Trainer
- **FR-033** Generate ShareLinks: static (players, unlimited, no expiry) and unique (coaches, single-use, 7-day). **Priority: H** *(US-01.02, US-01.08)*
- **FR-034** View player availability ("Best Times") for scheduling; filter players by availability. **Priority: M** *(US-01.09)*
- **FR-035** Assign coaches to events with availability checks (event linkage lands in Epic-02; this epic exposes the check). **Priority: M** *(US-01.10)*
- **FR-036** Manage own organization's users only (multi-tenancy boundary). **Priority: H** *(§9)*
- **FR-037** Portal branding: logo upload (PNG/JPG/SVG ≤2MB, ~200×200, auto-resize) + primary color (hex), live preview, org-wide apply. **Priority: M** *(US-01.14)*

### Cross-role / Profile
- **FR-038** Any user edits own profile (common + role-specific fields; email/role/skill-level read-only). Photo upload → file storage + thumbnail. **Priority: H** *(US-01.11)*
- **FR-039** Player/Parent sets "Best Times" availability per player (per child via switcher). **Priority: H** *(US-01.09)*
- **FR-040** Camp-to-User conversion stub: accept pre-fill payload + auto-assign trainer (full flow owned by Epic-08; this epic exposes the conversion endpoint contract). **Priority: M** *(§3, Epic-08 integration)*

## Business Rules

- **BR-001** Exactly one role per user; permissions enforced API + UI. *(§9)*
- **BR-002** Only Super Admin creates trainers; no trainer self-registration. *(§9)*
- **BR-003** Coach active under exactly one trainer at a time. *(§9)*
- **BR-004** Player↔trainer is many-to-many via association records; new link ≠ new account. *(§9)*
- **BR-005** Multi-trainer players get fully isolated per-context views (no unified view). *(§9)*
- **BR-006** **All under-18 are parent-managed; no independent minor accounts** (D-2). *(§9 line 739)*
- **BR-007** Parent owns all family contact info; each child has independent calendar/RSVP/Best-Times per trainer. *(§9)*
- **BR-008** USD child purchases always require parent approval; token approval is a per-child toggle (default ON=require). Requests expire 48h → auto-deny. *(US-01.05, §9)*
- **BR-009** Super Admin cannot impersonate other Super Admins; sessions logged; 1h expiry. *(§9)*
- **BR-010** Soft-delete preserves all history & is reversible; GDPR-delete anonymizes PII, is permanent, keeps analytics totals. *(§9)*
- **BR-011** Static ShareLinks: unlimited uses, no expiry. Unique coach links: single-use, 7-day expiry. Usage tracked (feeds Epic-06). *(§9)*
- **BR-012** Availability is advisory (scheduling suggestion), not a hard restriction; coach conflicts overridable with logged reason. *(§9)*
- **BR-013** Validation: email format + uniqueness; phone format; required name+email; child age 1–18; unique ShareLink codes; duplicate-name/age warning. *(§9)*
- **BR-014** Email verification required before first login (D-1). *(D-1)*
